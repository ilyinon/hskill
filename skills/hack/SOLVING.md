# Choosing the next useful action

Use the relevant section for stalled tasks, ambiguous evidence, or combined
capabilities. Topic diagnostics supply concrete branches; ordinary work does not
require another full workflow.

## Define completion

| Task | Completion evidence |
|---|---|
| Code audit | Actual source path, required policy, missing/effective control, bounded impact. |
| Fix/debug | Addressed mechanism, working legitimate case, regression control for the failed assumption. |
| Authorized lab/puzzle | Requested value, prediction, marker or local effect independently checked under the supplied construction. |
| Capture/artifact analysis | Recovered bytes/events tied to format/stream locations, with gaps and attribution limits. |

Keep the user's criterion. An intermediate needs remaining prerequisites;
sufficient source evidence can complete an audit. A requested proof need not
expand into further impact. For competing routes,
[work backward from the result](references/backward-planning.md).

## Choose a discriminating check

Record necessary facts with source/packet/request locations; separate assumptions
and unknowns. Choose a small permitted check whose predicted outcomes distinguish
the leading explanations. Resolve a prerequisite before repeating equivalent
payloads. A known-good baseline distinguishes tool/format failures from negatives.
For fragile calls, [preflight arguments](references/tool-contracts.md).

For changing inputs or context resets, keep an
[evidence state](references/evidence-state.md). Challenge consequential conclusions
with a plausible alternative using a [refutation pass](references/refutation.md).

## Interpret failure before retrying

| Failure | What it supports | Next action |
|---|---|---|
| Setup/tool failure before operation | Operation untested | Correct syntax/version/representation or use equivalent inspection. |
| Missing prerequisite | Technique inapplicable under observed conditions | Choose a compatible method; keep unrelated boundaries open. |
| Controlled negative | Tested path failed under those conditions | Update the hypothesis or conclude within scope. |
| Missing/noisy evidence | Outcome unknown | Obtain the smallest missing fact or state the limit. |

Change one causal dimension at a time. Retry when a new hypothesis predicts an
informative outcome. Equivalent failures do not justify unbounded search; a
malformed attempt does not establish class-wide safety.

## Join capabilities toward the goal

Keep `capability → required condition → next effect`, with evidence or an unknown
on each edge. Select the earliest unresolved edge needed by the goal. Readable
bytes are not accepted identity; a word list is not a prediction; control transfer
is not a working process effect.

Check [edge contracts](references/chain-contracts.md) where proven steps may not
compose. Use [staged progress](references/staged-progress.md) for delayed evidence
or failed tools. Retain partial results when an edge needs unavailable access or
an unapproved action; reuse authorization and clarify only genuine blockers.

For fragile arithmetic/state reasoning, use a
[small executable model](references/executable-models.md). A fix must preserve
valid behavior: [minimize a working proof](references/minimization.md) when its
cause is unclear and use applicable [metamorphic checks](references/metamorphic-checks.md)
to challenge generalization.

## Transfer mechanisms from worked cases

Read a case matching the unresolved mechanism. Extract why the first approach
failed, which observation changed it, and how the result was independently checked.
Re-establish prerequisites. Synthetic examples verify supplied models, not every
runtime or configuration.
